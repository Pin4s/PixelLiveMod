# PixelLiveMod TikTok connector

Requires Node.js 20+ and the PixelLiveMod 0.7.0 plugin in the isolated game copy.

1. Copy `../.env.example` to `../.env` and set `TIKTOK_USERNAME` to a public LIVE account, with or without `@`. Paste an optional Euler Stream API key into `EULER_STREAM_API_KEY` in the same file. Set `PIXELLIVEMOD_BRIDGE_PORT` to the same value as `[Bridge] Port` in the game's BepInEx config (default 19081). The connector loads the project root `.env` automatically; existing environment variables take precedence.
2. Copy `config.example.json` to `config.json` (kept local and ignored by Git). This file contains gift mappings and per-gift quantities. Restart the connector after configuration changes.

`config.json` also controls free engagement rewards: `followRewardEnabled` (true), `followRewardBallType` (`Pink`), `followRewardBallQuantity` (3), `likeRewardEnabled` (true), `likeRewardThreshold` (100), `likeRewardBallType` (`Orange`), and `likeRewardBallQuantity` (1). Quantities must be 1..20. The connector retains follow IDs and like progress in memory for the current numeric TikTok Room ID; game round resets do not clear them. A new Room ID starts a new session. Restarting the connector itself clears this in-memory state.

The installed `tiktok-live-connector@2.5.0` emits `follow` only for a `WebcastSocialMessage` whose `common.displayText.key` contains `follow`. `member`/room entry events are ignored. The reward requires a stable numeric `user.id`/`user.userId` and is issued once per viewer per Room ID. The v3 `like` protobuf supplies the user's increment in `count` and the room-wide total in `total`; older payloads may expose `likeCount` and `totalLikeCount`. Only the increment is applied to that user's counter. A stable numeric viewer ID and message ID are required, and message IDs remain deduplicated across reconnections to the same Room ID. The room-wide total is never used for an individual's progress. Likes missed while disconnected cannot be recovered from the room total, and TikTok does not provide enough information to deduplicate a replay assigned a new message ID.

Follow and like commands use the existing TCP spawn queue with `source` and, for likes, the viewer's `milestone`. Gift and like balls receive the viewer as their owner and score actual destroyed pixels through the existing Pixels Podium rules. Follow and hotkey balls remain unowned. The feed displays rewards after actual ball creation, and a canceled reward's uncreated remainder is retried in the next round. A lost bridge acknowledgment still has an uncertain outcome and is not automatically resent. To check in a real LIVE, have two viewers like separately: 70+30 from one viewer and 80+20 from the other should produce one Orange ball each. Confirm their ball kills score under their respective names. Reconnect to the same Room ID and confirm their remaining progress is retained. A new LIVE must have a new Room ID.
3. In this directory, run `npm ci`, `npm run build`, `npm test`, then `npm start`. Tests read the example config and do not require a live username.
4. Start the isolated game with `Start-Isolated-Game.cmd` in the parent project directory. The connector retries the local bridge if the game starts later.

The nine ball gifts retain independent `quantity` values (1..20 per gift). Galaxy is a tenth, special action: it sends `GalaxyReset` and creates no ball. The example uses 1000 coins; the configured cost is checked against the room catalog, so set it to the value shown in your LIVE catalog if different. Both `Galaxy` and `Galáxia` names are recognized. `coins` is an identity check, not an input for ball quantity. Optional numeric-string `giftId` may be added after a verified room catalog lookup; it is never guessed. If catalog lookup fails, event fallback requires exact name and cost, and any configured ID must also match.

The connector uses `tiktok-live-connector@2.5.0`, an unofficial library. Its public connection uses Euler Stream signing with community rate limits; an optional API key comes only from `EULER_STREAM_API_KEY`, and no account cookies are configured here. Catalog lookup may fail or a public LIVE may be offline, in which case the program logs the failure from each Room ID source and retries after 30 seconds. When Euler Stream returns a rate limit, the connector logs the actual error and waits at least the server's `retry-after` interval before reconnecting. If the account is live and you have verified its current numeric Room ID, optionally set `TIKTOK_ROOM_ID` in the project root `.env` to bypass username lookup; remove it when the live ends. Neither a LIVE connection nor gift receipt is implied by a successful local build.

TCP listens only on `127.0.0.1`. Each JSON-line command has a unique `requestId`, `type`, and `quantity` (1..20). The Unity response says whether the command was accepted *into the spawn queue*, not whether every ball was created. Actual creation/failure appears in `BepInEx/LogOutput.log`. A command with a lost acknowledgment is never resent automatically; its outcome is explicitly uncertain.

For gifts with a stable numeric viewer ID and public name, commands also carry `batchId`, `viewerId`, `viewerName`, `giftId`, `giftName`, and incremental `giftUnits`. All chunks from one gift event use the same batch ID. The plugin associates this data with each accepted command and updates the in-game feed only after the spawn service reports the number actually created. Commands without gift metadata remain valid and never appear in the feed.

To check the feed and podium without TikTok, start the isolated game, enter a playable scene, then run `npm run build` and `npm run simulate:feed` here. The script sends one simulated Rose from `teste_a`, three more two seconds later, and one from `teste_b`. It deliberately spawns five Orange balls in the active game with two distinct viewer IDs. It is a separate command and is never run by `npm start`.
